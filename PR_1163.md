## Summary

Implements per-asset contract-wide daily outflow limits so a fresh/sybil address
is never unlimited, plus an optional per-asset default per-source limit.

- Added `DataKey::AssetDailyLimit(asset)`, `DataKey::AssetDailyUsage(asset, day)`
  and `DataKey::DefaultSourceDailyLimit(asset)`.
- `check_daily_limit` now evaluates the explicit per-source limit (or the new
  fallback when no explicit entry exists) **and** the contract-wide asset cap,
  and only records usage after every applicable check passes (no quota is
  consumed by a rejected transfer). All existing funding paths call it.
- The relayed `fund_c_address_crosschain` payout path calls
  `check_asset_daily_limit` too, so cross-chain outflow is capped as well.
- New admin API with sequential nonce, events and persistent TTL:
  `set_asset_daily_limit`, `set_default_source_daily_limit`, plus query helpers
  (`query_asset_daily_limit`, `query_asset_daily_usage`,
  `query_default_source_daily_limit`, `query_source_daily_usage`).
- Asset limits are included in the `emergency_migrate` per-asset snapshot and
  in `extend_persistent_ttl`.
- New error `AssetDailyLimitExceeded = 53`; README documents the limit
  precedence (`explicit source` > `default source`, asset cap applies to all).

### Pre-existing build blockers fixed (required to run any test)

- `#[contracterror]` panicked at macro expansion because `BridgeError` had 52
  variants while the Soroban XDR spec caps error enums at 50. Spec export is
  disabled for this enum (all discriminants and `TryFrom<Error>` mappings kept).
- `DataKey` hit the same 50-case cap after adding the three new keys, so its
  unused internal spec export is disabled too.
- `remove_relayer` referenced an undefined `was_registered` local.
- Seven stale test calls omitted the `nonce` argument; four test modules had a
  redundant inner `#![cfg(test)]` flagged by clippy.
